# 学习操作系统

这份文档定义**我们怎么学**，比学什么更重要。

## 核心规则

### 规则 1：先自己答，再看答案

任何技术问题，顺序永远是：

```text
你自己回答（哪怕错）
  ↓
AI 指出问题在哪
  ↓
DeepSeek / GLM 作为第二导师（可选）
  ↓
画出完整调用链
  ↓
写最小实验 / Debug
  ↓
写学习日志
```

**不查资料、直接凭现有理解作答。答错比答对更有价值**——答错暴露的是真实的认知缺口，
答对只说明这个词你见过。

### 规则 2：不背答案，自己追

遇到框架行为，不查「标准答案」，而是：

```text
① 项目结构 → ② 启动入口 → ③ 核心调用链 → ④ 核心数据结构
→ ⑤ 一个真实请求 → ⑥ Debug → ⑦ 修改 → ⑧ 测试
```

用 `family_asset` 里真实的代码当靶子，而不是另起一个玩具项目。

### 规则 3：一切落到主项目

学到的每个能力，都要能在 `family_asset` 里找到落点。
找不到落点的知识，先记下来，不急着深挖。

### 规则 4：留痕

每天一份日志，写在 `learning/daily/YYYY-MM-DD-dayNN.md`。
日志的价值在 12 个月后——那时候你能看到自己是怎么一步步走过来的。

## 每天的结构

| 环节 | 内容 |
|------|------|
| 1. 提问 | 一个真问题（不是「介绍一下 XXX」） |
| 2. 自答 | 不查资料，写下来 |
| 3. 纠偏 | AI 指出问题 + 追调用链 |
| 4. 实验 | 在 `family_asset` 上验证 |
| 5. 英语 | 20 分钟，主题 = 当天的技术主题 |
| 6. 日志 | 填 `daily/` 当天文件 |

## 目录

```text
learning/
├── README.md                  # 本文件：规则、节奏
├── ROADMAP.md                 # 12 个月路线图
├── daily/                     # 每日学习日志
└── templates/
    └── daily-template.md      # 日志模板
```

## 一个提醒

> 这个计划的敌人不是「难」，是「断」。

每天 1 小时连续 12 个月，远胜于每周突击 8 小时然后停三周。
如果某天只有 20 分钟，就只做「提问 + 自答」两件事，也算完成。
