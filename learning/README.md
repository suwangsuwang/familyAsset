# 学习操作系统

这份文档定义**我们怎么学**，比学什么更重要。

## 核心规则

### 规则 1：先自己答，再看答案

任何技术问题，顺序永远是：

```text
你自己回答（哪怕错）
  ↓
AI 指出问题在哪
  ↓
DeepSeek / GLM 作为第二导师（可选）
  ↓
画出完整调用链
  ↓
写最小实验 / Debug
  ↓
写学习日志
```

**不查资料、直接凭现有理解作答。答错比答对更有价值**——答错暴露的是真实的认知缺口，
答对只说明这个词你见过。

### 规则 2：不背答案，自己追

遇到框架行为，不查「标准答案」，而是：

```text
① 项目结构 → ② 启动入口 → ③ 核心调用链 → ④ 核心数据结构
→ ⑤ 一个真实请求 → ⑥ Debug → ⑦ 修改 → ⑧ 测试
```

用 `family_asset` 里真实的代码当靶子，而不是另起一个玩具项目。

### 规则 3：一切落到主项目

学到的每个能力，都要能在 `family_asset` 里找到落点。
找不到落点的知识，先记下来，不急着深挖。

### 规则 4：留痕

每天一份日志，写在 `learning/daily/YYYY-MM-DD-dayNN.md`。
日志的价值在 12 个月后——那时候你能看到自己是怎么一步步走过来的。

## 每天的结构

| 环节 | 内容 |
|------|------|
| 1. 提问 | 一个真问题（不是「介绍一下 XXX」） |
| 2. 自答 | 不查资料，写下来 |
| 3. 纠偏 | AI 指出问题 + 追调用链 |
| 4. 实验 | 在 `family_asset` 上验证 |
| 5. 英语 | 20 分钟，主题 = 当天的技术主题 |
| 6. 日志 | 填 `daily/` 当天文件 |

## 三个平台的分工

| 平台 | 定位 | 负责 |
|------|------|------|
| **网页 ChatGPT** | 总教练 / 学习中枢 | 路线、今天学什么、知识体系、进度、复盘、出题 |
| **VS Code + Claude Code** | 实验室 / 编程现场 | 读代码、改代码、跑、Debug、写测试、Git、真实实验 |
| **DeepSeek / GLM** | 第二、第三位专家 | Code Review、质疑、并发/一致性/性能审查 |

```text
              你
              │
      ┌───────┼────────┐
      ↓       ↓        ↓
 ChatGPT  Claude Code  DeepSeek/GLM
   │          │           │
 教学        写代码       Review
 路线        Debug        质疑
 复盘        实验         第二意见
```

大致比例（随阶段浮动）：理论学习 ChatGPT 50% / IDE 20% / Review 30%；
做项目 ChatGPT 20% / IDE 60% / Review 20%。

**基础知识问题在网页里问，不在 IDE 里问。** IDE 里只做一件事：
「这个项目现在具体应该怎么改？」

## 学习流水线（每个技术点都走一遍）

```text
① 网页  理解原理
② 网页  给你出问题
③ IDE   找真实代码（只读，不改）
④ 你    自己设计
⑤ 你    自己写
⑥ IDE   运行 / Debug
⑦ DeepSeek  Code Review
⑧ GLM       第二次 Review
⑨ 网页  总结知识 + 复盘
⑩ Git   Commit + 学习日志
```

**铁律：不要让 AI 一开始就写代码。** 先理解、先自己设计、先自己实现，
AI 只在「找代码」「Review」「Debug」这三个位置介入。

## 一个提醒

> 这个计划的敌人不是「难」，是「断」。

每天 1 小时连续 12 个月，远胜于每周突击 8 小时然后停三周。
如果某天只有 20 分钟，就只做「提问 + 自答」两件事，也算完成。
